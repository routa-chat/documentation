`routa.messages` cobre o ciclo de vida das mensagens. Cada método corresponde a um endpoint da [API REST](/api-reference/endpoint/messages/send).

## `send`

Envia texto ou um template aprovado. Retorna a mensagem no estado `accepted`.

```ts
const message = await routa.messages.send({
  channel: 'chan_...',
  to: '+5581999999999',
  text: 'Olá! Seu pedido foi confirmado.',
  metadata: { order_id: '1234' },
})

console.log(message.id, message.status) // "msg_...", "accepted"
```

| Parâmetro | Descrição |
| --- | --- |
| `channel` | Id do canal (`chan_...`). |
| `to` | Destinatário em E.164. O `+` inicial é opcional. |
| `text` | Corpo da mensagem. Mutuamente exclusivo com `template`. |
| `template` | `{ id, bodyParameters? }`. Mutuamente exclusivo com `text`. |
| `metadata` | Até 20 pares chave-valor de texto. |
| `idempotencyKey` | Reutilizada em toda retentativa. Por padrão o SDK gera uma. |

Enviar um template:

```ts
await routa.messages.send({
  channel: 'chan_...',
  to: '+5581999999999',
  template: { id: 'tmpl_...', bodyParameters: ['Ana', '#1234'] },
})
```

<Warning>
  `accepted` não significa entregue. Acompanhe a entrega por [webhooks](/sdk/webhooks). Veja [Acompanhar a entrega](/guides/track-delivery).
</Warning>

## `retrieve`

Retorna uma mensagem pelo id.

```ts
import { isMessageId, toMessageId } from '@routa-chat/sdk'

// Um id que você já considera confiável, como um guardado de um envio anterior:
const message = await routa.messages.retrieve(toMessageId('msg_01J8ZK9M3Q7XABCDEFGHJKMNPQ'))
console.log(message.status, message.deliveredAt)

// Um id vindo de uma entrada do usuário ou de uma URL: valide o formato antes.
function lookUp(id: string) {
  if (!isMessageId(id)) {
    throw new Error(`Not a message id: ${id}`)
  }
  return routa.messages.retrieve(id)
}
```

Os ids são tipos *branded*: um `MessageId` é uma string em runtime, mas uma `string` comum não é atribuível a ele. Veja [Tipos e IDs](/sdk/typescript).

## `list`

Lista mensagens com paginação automática. Filtre por `direction` para ver só as recebidas ou só as enviadas.

```ts
for await (const message of routa.messages.list({ direction: 'inbound', limit: 50 })) {
  console.log(message.id, message.from, message.content)
}
```

Para controlar a paginação manualmente, peça uma página por vez:

```ts
const page = await routa.messages.list({ limit: 20 }).page()
console.log(page.data.length, page.hasMore, page.nextCursor)
```

Veja [Paginação](/sdk/pagination).

## `markRead`

Marca uma mensagem **recebida** como lida e envia a confirmação de leitura ao remetente.

```ts
const message = await routa.messages.markRead(messageId)
console.log(message.status) // "read"
```

Para uma mensagem enviada por você, a API responde `422 message_direction_invalid`.

## O objeto `Message`

Os campos do SDK são os da API em *camelCase*.

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `id` | `MessageId` | Identificador. |
| `channel` | `string` | Canal usado. |
| `direction` | `'outbound' \| 'inbound'` | Direção. |
| `from`, `to` | `string` | Endereços em E.164. |
| `content` | `MessageContent \| null` | Conteúdo, discriminado por `type`. É `null` quando a retenção removeu o conteúdo. Vale a partir da 0.2.0. Na 0.1.0 o tipo é `MessageContent`. |
| `status` | `MessageStatus` | `accepted`, `sent`, `delivered`, `read` ou `failed`. |
| `metadata` | `Record<string, string>` | Metadados do cliente. |
| `acceptedAt` | `string` | ISO 8601, sempre presente. |
| `sentAt`, `deliveredAt`, `readAt`, `failedAt` | `string \| null` | Momento de cada etapa. |
| `contentRedactedAt` | `string \| null` | ISO 8601. Quando a retenção removeu o conteúdo, ou `null` enquanto a mensagem ainda o tem. Vale a partir da 0.2.0. |
| `_replayed` | `boolean` | `true` quando a chamada devolveu o resultado de uma tentativa anterior com a mesma `Idempotency-Key`. |

### Mensagens com conteúdo removido

A Routa remove o conteúdo de uma mensagem depois do período de retenção do plano. A API devolve essa mensagem com `content: null` e `content_redacted_at`. O restante dela continua. Veja [Conteúdo removido pela retenção](/concepts/messages#conteúdo-removido-pela-retenção).

O SDK trata isso de forma diferente em cada versão:

- **Na 0.1.0:** `content` é tipado como `MessageContent`, sem `null`, e `contentRedactedAt` não existe. `messages.retrieve()` e `messages.list()` lançam `TypeError` ao encontrar uma mensagem com o conteúdo removido. Uma só dessas mensagens derruba a listagem inteira. Se você usa a 0.1.0 e tem mensagens mais antigas que a retenção, atualize para a 0.2.0 ou leia as mensagens pela [API REST](/api-reference/endpoint/messages/list).
- **A partir da 0.2.0:** `content` é `MessageContent | null` e `contentRedactedAt` é `string | null`. Essas mensagens são devolvidas normalmente. Como o tipo de `content` mudou, o código que lê `message.content` sem verificar deixa de compilar. Proteja a leitura:

```ts
for await (const message of routa.messages.list({ limit: 50 })) {
  if (message.content) {
    console.log(message.id, message.content.type)
  } else {
    console.log(message.id, 'conteúdo removido em', message.contentRedactedAt)
  }
}
```

<Note>
  **Ainda não suportado em nenhuma versão.** A API devolve `failure_code` em uma mensagem que falhou, mas o SDK não o inclui: `failureCode` não está nos tipos nem no objeto devolvido. Leia o motivo da falha pela [API REST](/api-reference/endpoint/messages/retrieve).
</Note>

`MessageContent` cobre também tipos que só chegam em mensagens recebidas ou no histórico (mídia, localização, reação) e `unsupported`, para que ler uma mensagem não lance erro só porque o tipo de conteúdo ainda não é enviável. Isso é independente do `null` descrito acima, que indica conteúdo removido, não um tipo desconhecido.
